# 의견 기능 개발 안내

이 디렉터리의 화면은 제안 상세 페이지와 백엔드 API가 준비되기 전에 의견 작성 및 목록 UI를 독립적으로 확인하기 위한 개발용 화면입니다.

## 현재 구현 범위

- 찬성, 조건부 찬성, 반대 선택
- 코멘트 validation 및 자동 높이 조절
- Mock 의견을 초기값으로 사용하는 React state
- 새 의견 제출 시 목록에 즉시 반영
- 작성자 이름, 소속 기업, 의견 상태, 코멘트, 작성 시간 표시
- 작성 시간을 각 사용자의 브라우저 현지 시간대로 표시
- 의견 요약 버튼 클릭 시 Mock 로딩 후 같은 화면의 모달에 요약 표시

현재 데이터는 새로고침하면 초기화되며 실제 서버에는 저장되지 않습니다.

## 개발 화면 접속

프로젝트 루트에서 개발 서버를 실행합니다.

```powershell
npm.cmd run dev
```

브라우저에서 아래 주소로 접속합니다.

```text
http://localhost:5173/?consensus-dev
```

`App.tsx`에는 위 쿼리 문자열이 있을 때만 `ConsensusDevPage`를 보여주는 임시 조건이 추가되어 있습니다. 실제 라우터와 제안 상세 페이지에 연결한 뒤 이 조건과 개발 페이지는 제거할 수 있습니다.

## 실제 페이지 연결에 필요한 선행 작업

### 1. 제안 상세 페이지 및 제안 식별자

프론트 1 담당 영역의 제안 상세 페이지가 준비되어야 합니다. 실제 화면에서는 다음과 같이 URL의 `proposalId`를 기준으로 의견을 조회하고 등록하는 구조가 필요합니다.

```text
/proposals/:proposalId
```

제안 제목과 본문은 제안 상세 페이지에서 표시하고, 현재 구현한 `OpinionForm`과 `OpinionList`는 그 페이지 내부의 의견 영역으로 연결하는 것을 권장합니다.

### 2. React Router 및 공통 레이아웃

프론트 3 담당 영역의 Router, Header, Sidebar 등 공통 구조가 준비되면 임시 쿼리 방식 대신 정식 제안 상세 경로에 컴포넌트를 배치해야 합니다.

### 3. 로그인 사용자 정보

현재 `ConsensusDevPage`는 임시 작성자 정보를 사용합니다. 로그인 기능이 준비되면 `OpinionForm`의 `author` prop에는 인증된 현재 사용자 정보를 전달해야 합니다.

### 4. 백엔드 의견 API

API 명세가 확정되면 다음 기능이 필요합니다.

- 제안별 의견 목록 조회
- 의견 등록
- 동일 사용자의 중복 제출 처리
- 제출 성공 및 실패 처리
- 서버 작성 시간과 사용자/기업 정보 매핑

API 호출 코드는 UI 컴포넌트에 직접 작성하지 않고 추후 `src/api/opinionApi.ts`로 분리합니다. 엔드포인트와 요청·응답 타입은 백엔드 명세가 확정된 뒤 정의합니다.

## 컴포넌트 연결 구조

```text
제안 상세 페이지
└─ 의견 영역
   ├─ OpinionForm
   └─ OpinionList
      └─ OpinionCard
```

`OpinionForm`은 완성된 `Opinion`을 `onSubmit`으로 부모에 전달하고, `OpinionList`는 부모가 관리하는 `opinions` 배열을 표시합니다. 실제 API 연동 시에도 부모 화면이 조회 및 제출 상태를 관리하는 구조를 유지할 수 있습니다.
